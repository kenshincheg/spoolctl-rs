# План разработки SpoolCtl

## Цель

Portable-утилита на Rust: перезапуск службы печати (Spooler) и очистка очереди, когда служба «висит». Функции добавляются по одной.

## Совместимость

| Цель | Решение |
|------|---------|
| Windows 10 / 11 x64 | Основная цель с первого дня (ядро + GUI) |
| Windows 7 x64 | Ядро (SCM + файлы очереди) с совместимыми API; GUI — после smoke-теста |
| Windows 7 x86 | Отложено |

Если GUI на Win7 не встанет стабильно — для Win7 остаётся CLI; GUI остаётся для 10/11.

Опасные операции только с правами администратора (UAC).

## Границы текущей стабильной линии (0.1.15)

**Делаем / сделано**

- статус службы Spooler;
- стоп / старт / перезапуск;
- очистка очереди: stop → удаление заданий в `%SystemRoot%\System32\spool\PRINTERS` → (опционально) start;
- журнал без секретов;
- portable EXE; лог рядом с EXE или в `%LOCALAPPDATA%\SpoolCtl\logs`;
- GUI Win10/11, трей, сторож зависания, elevated-автозапуск.

**Сознательно не делаем** (см. раздел «Вне скоупа» ниже)

- удалённое управление другими ПК;
- полный аналог printmanagement.msc;
- установка / обновление драйверов и принтеров;
- автозапуск «по зависанию» без явного согласия.

## Технологии

- Rust + crate `windows` (Service Control Manager, Winspool, Task Scheduler).
- Очередь — файловая очистка при остановленном Spooler.
- GUI: `eframe` (Glow, запасной wgpu).
- CLI: `status`, `restart`, `clear-queue`, `fix` (для скриптов и Win7).

## Вне скоупа — подробно

Эти три направления **не входят** в SpoolCtl сейчас и не планируются «заодно». Ниже — что это значит на практике, зачем их обычно хотят и почему они отдельный продукт.

### 1. Удалённое управление другими ПК

**Что это.** Управление Spooler / очередью / статусом печати **на другом компьютере** из одной консоли: по сети (RPC, WinRM/PowerShell Remoting, свой агент + HTTPS, RMM вроде Intune/Action1 и т.п.).

**Типичные сценарии**

- админ в серверной чинит «зависшую печать» на 20 рабочих местах без TeamViewer к каждому;
- helpdesk: «очисти очередь на `PC-Бухгалтерия-03`»;
- мониторинг: алерт, что Spooler на хосте Stopped / очередь не двигается.

**Что пришлось бы сделать технически**

- канал связи (учётка домена / сертификаты / firewall);
- права на удалённый SCM и на `spool\PRINTERS` на целевом ПК;
- агент или разрешённый WinRM; аутентификация, аудит «кто что сделал»;
- модель угроз: злоумышленник с доступом к консоли = stop Spooler / wipe очереди на парке машин.

**Почему не в SpoolCtl.** Сейчас это **локальный portable EXE** «на этом ПК, с согласия пользователя (UAC)». Удалёнка меняет продукт: сервер/агент, безопасность, поддержка, совсем другой объём тестов. Ближайший честный путь без своего бэкенда — скрипт + `SpoolCtl.exe` по WinRM/`PsExec`, но это уже инфраструктура админа, не фича GUI.

### 2. Полный аналог printmanagement.msc

**Что это.** Оснастка **«Управление печатью»** (Print Management): серверы печати, очереди, драйверы, порты, формы, фильтры развёртывания, права на принтер, миграция очередей, просмотр заданий по серверу.

**Что умеет оснастка (и чего нет у SpoolCtl)**

| Область | printmanagement.msc | SpoolCtl |
|--------|---------------------|----------|
| Служба Spooler stop/start/restart | косвенно / через службы | **да, ядро** |
| Очистка зависших файлов очереди | вручную / скрипты | **да, ядро** |
| Список локальных принтеров / число заданий | да | кратко в GUI/CLI |
| Общие принтеры, ACL, кто печатает | да | нет |
| Порты (TCP/IP, WSD), формы, языки | да | нет |
| Несколько серверов печати в одном дереве | да | нет |
| Фильтры «принтеры с ошибкой» по домену | да | нет |

**Почему не клонируем.** Это большой MMC-продукт Microsoft с кучей Print Spooler API, политик и сценариев сервера печати. SpoolCtl закрывает узкую боль: **«служба зависла / очередь залипла — починить быстро»**. Список принтеров у нас — обзор, не консоль администрирования.

### 3. Установка и обновление драйверов / принтеров

**Что это.** Добавить принтер, поставить/обновить драйвер (INF/CAB/пакет производителя), сменить порт, развернуть драйвер на сервер печати (`pnputil`, PrintUI, драйвер-стор Windows Update / каталог вендора).

**Типичные сценарии**

- «после обновления Windows пропал принтер — поставь драйвер HP/Kyocera»;
- массовая раскатка одного драйвера на пул машин;
- смена порта с WSD на TCP/IP с фиксированным адресом.

**Почему опасно и не в скоупе**

- драйверы печати работают в контексте Spooler (часто SYSTEM): плохой драйвер = BSOD / вечный hang (как раз то, от чего SpoolCtl лечит симптомы);
- нужен каталог проверенных пакетов, подпись, архитектура x64/ARM, версии ОС;
- UI выбора INF, тихие установки, откат — отдельный продукт уровня «printer deployer»;
- антивирусы и SmartScreen особенно чувствительны к «EXE кладёт файлы в System32 и трогает Spooler».

**Что SpoolCtl делает рядом, но это не драйверы:** подсказка по типу порта (USB/WSD/IP), кнопка «Папка принтеров», отключение автонастройки Ncd/WSD — помощь админу **диагностировать**, не ставить софт вендора.

## Риски

1. Win7 + современный GUI — главный риск; ядро раньше GUI; в ZIP — CLI-папка.
2. Очистка при running Spooler запрещена — всегда stop first.
3. Права на файлы в `spool\PRINTERS` — нужен администратор.
4. Антивирусы могут насторожиться на stop + delete в System32 — прозрачный журнал.
5. Автоперезапуск и elevated-автозапуск — только с явным согласием; ложные срабатывания сторожа возможны на медленных принтерах.

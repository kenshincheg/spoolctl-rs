# План разработки SpoolCtl

## Цель

Portable-утилита на Rust: перезапуск службы печати (Spooler) и очистка очереди, когда служба «висит». Функции добавляются по одной.

## Совместимость

| Цель | Решение |
|------|---------|
| Windows 10 / 11 x64 | Основная цель с первого дня (ядро + GUI) |
| Windows 7 x64 | Ядро (SCM + файлы очереди) с совместимыми API; GUI — после smoke-теста |
| Windows 7 x86 | Отложено |

Если GUI на Win7 не встанет стабильно — для Win7 остаётся CLI; GUI остаётся для 10/11.

Опасные операции только с правами администратора (UAC).

## Границы первой версии

**Делаем**

- статус службы Spooler;
- стоп / старт / перезапуск;
- очистка очереди: stop → удаление заданий в `%SystemRoot%\System32\spool\PRINTERS` → start;
- журнал без секретов;
- portable EXE; лог рядом с EXE или в `%LOCALAPPDATA%\SpoolCtl\logs`.

**Не в v1**

- удалённое управление другими ПК;
- полный аналог printmanagement.msc;
- автозапуск «по зависанию» без явного согласия;
- установка драйверов / принтеров.

## Технологии

- Rust + crate `windows` (Service Control Manager).
- Очередь — файловая очистка при остановленном Spooler.
- GUI позже: `eframe` + Glow (OpenGL), без WGPU/DX12.
- CLI: `status`, `restart`, `clear-queue` (для скриптов и Win7).

## Правило продвижения

1. Согласована модель и опасные сценарии.
2. Реализованы backend и (при необходимости) UI только этой функции.
3. Тесты логики без Win32 + ручная проверка.
4. Журнал, понятные ошибки.
5. `cargo fmt`, `clippy -D warnings`, `cargo test`.
6. Только после этого — следующая функция.

## Этапы

### Этап 0 — каркас

- Репозиторий, README, план, журнал.
- Минимальный бинарь и зависимости SCM.

**Готово, когда:** проект собирается, план зафиксирован.

### Этап 1 — статус и управление службой

- Query / Stop / Start / Restart `Spooler`.
- Ожидание целевого состояния с таймаутом.
- CLI: `status`, `stop`, `start`, `restart`.

**Готово, когда:** ручной перезапуск на тестовой Win10/11; ошибки читаемы.

### Этап 2 — очистка очереди

- Только при остановленном Spooler (или атомарно: stop → clear → start).
- Отчёт: сколько файлов удалено / что не удалось.
- CLI: `clear-queue` / `fix` (очистить + перезапустить).

**Готово, когда:** сценарий проверен на машине с зависшей/забитой очередью.

### Этап 3 — GUI (Win10/11)

- Статус, кнопки: Перезапуск | Очистить очередь и перезапустить.
- UAC elevation.
- Подтверждение перед очисткой.

### Этап 4 — UX и надёжность

- Таймауты, индикатор занятости, журнал.
- Защита от повторного запуска операции.

### Этап 5 — Win7

- Smoke ядра на Win7 x64.
- При проблемах GUI — CLI + bat; GUI для 10/11.

### Этап 6 — выпуск

- Portable-сборка, ZIP + SHA256, заметки релиза.

**Готово (0.1.0).**

## Риски

1. Win7 + современный GUI — главный риск; ядро раньше GUI.
2. Очистка при running Spooler запрещена — всегда stop first.
3. Права на файлы в `spool\PRINTERS` — нужен администратор.
4. Антивирусы могут насторожиться на stop + delete в System32 — прозрачный журнал.
